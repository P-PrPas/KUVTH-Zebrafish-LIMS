🔴 ต้องแก้ก่อน merge

"ทำสำเนาการทดลอง" ใช้ตั้งชื่อผู้ปฏิบัติงานเป็นคนอื่นได้ (ทดสอบจริง)
- Member Toon กด duplicate การทดลองของ Bee แล้วได้การทดลองใหม่ที่บันทึกเป็น Bee (201)
- สาเหตุ: POST /batches/{id}/duplicate คัดลอก operatorId จากต้นฉบับ แต่การตรวจใน validate_write_context ดูเฉพาะ operatorId ใน body ซึ่ง endpoint นี้ไม่มี
- วิธีแก้: ตอน duplicate ถ้าผู้ทำเป็น member ให้ตั้ง operatorId ของการทดลองใหม่เป็น operator ที่ผูกกับบัญชี (หรือใช้ X-Operator-Id ที่ผ่านการตรวจแล้ว) และเพิ่ม test

🟡 ควรแก้ / ต้องตัดสินใจ

- Log ผิดระดับ: ขอรหัสซ้ำระหว่าง cooldown แล้ว server เขียน traceback เต็มระดับ ERROR ว่า "Sign-in code delivery failed" ทั้งที่เป็น rate limit ปกติ (ทดสอบแล้ว 4 ครั้งต่อการขอซ้ำ 4 ครั้ง) ทำให้ alert ทำงานผิด และใครก็ทำให้ log ล้นได้ ควรจับ APIError 429 แยกแล้ว log เป็น info ไม่ต้องมี traceback
- Policy ที่ต้องตัดสินใจ: member แก้ข้อมูลการทดลองของ operator อื่นไม่ได้เลย แม้แค่หมายเหตุ (403 operator_mismatch) แต่ยังบันทึกผลตรวจในการทดลองนั้นได้ ถ้าตั้งใจเป็นแบบนี้ควรบันทึกเป็น policy และให้ UI ซ่อนปุ่มแก้ไขเพื่อไม่ให้ผู้ใช้เจอ error
