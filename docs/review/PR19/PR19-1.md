✅ ส่วนที่ทำได้ดี (ยืนยันด้วยการรันจริง)

- OTP: ใช้ secrets, เก็บแบบ HMAC-SHA256 และเทียบแบบ constant-time. ผิด 5 ครั้งแล้วรหัสนั้นใช้ไม่ได้, หมดอายุ 10 นาที, ใช้ซ้ำไม่ได้, cooldown 60 วินาที, ขอได้ไม่เกิน 5 ครั้งต่อชั่วโมง
- Email: รับเฉพาะ @ku.th (ปฏิเสธ @ku.th.evil.com) และไม่มีช่องให้ inject header
- Cookie: HttpOnly, SameSite=Lax, Secure เปิดไว้เป็นค่าเริ่มต้น เก็บเฉพาะ hash ของ token ใน DB. CSRF ป้องกันด้วย JSON content-type + custom header
- การบังคับ login: ทุก API ต้อง login (รวม export). Member ถูกบล็อกจาก admin API และการเขียน master data (403)
- Header X-Actor-User-Id: กันงานออฟไลน์ของ user A ไม่ให้ไป sync ภายใต้ user B
- Admin กันพลาด: admin คนสุดท้ายลดสิทธิ์ตัวเองไม่ได้. ปิดบัญชีแล้ว session ถูก revoke ทันที. ถ้าเครื่องยังมีงานค้างจะปิดบัญชีไม่ได้ และถ้าไม่รู้สถานะ sync ต้องยืนยันก่อน
- AUTH_SECRET บังคับต้องตั้งเมื่อไม่ใช่ dev/test
- Audit log เก็บ actor_email จาก session

🔴 ต้องแก้ก่อน merge

1. ผู้ปฏิบัติงานยังปลอมได้ (ทดสอบจริง)
- Server ยังเชื่อ X-Operator-Id จาก client โดยไม่เทียบกับ operator ที่ผูกกับบัญชี และ dropdown "ผู้ปฏิบัติงาน" ใน header (App.tsx:318) ยังให้เลือกใครก็ได้
- ผลทดสอบ: member ที่ผูกกับ Jan สร้างการทดลองที่บันทึกเป็น Bee ได้ (201). Audit log บันทึกว่า operator=Bee, actor=member.test@ku.th
- ตรวจย้อนหลังได้ แต่ข้อมูลวิจัยระบุคนทำผิด
- วิธีแก้: ถ้าบัญชีผูก operator ไว้ ให้ server ใช้ operator นั้นเสมอ (ปฏิเสธเมื่อไม่ตรง) และล็อก dropdown. ส่วน admin หรือบัญชีที่ไม่ได้ผูก ให้กำหนด policy ชัดเจน

2. Rollback migration 000012 บน MySQL พัง (ทดสอบจริง)
ERROR 1064 ... near 'IF EXISTS ix_audit_actor'
- MySQL 8.0 ไม่รองรับ DROP INDEX IF EXISTS และ DROP COLUMN IF EXISTS
- ยังมีปัญหาลำดับลบ index ก่อน FK แบบเดียวกับ 000011 ใน PR #18
- รอบนี้ fail ตั้งแต่บรรทัดแรกจึงไม่ทำให้ schema ค้างครึ่งทาง แต่ rollback บน MySQL ทำไม่ได้เลย
- วิธีแก้: ใน generator ให้แปลงทั้งสองคำสั่ง และลบ FK ก่อน index

3. Bootstrap admin และผู้ส่งเมลมีค่าเริ่มต้นเป็นอีเมลส่วนตัวของคุณ
- config.py: BOOTSTRAP_ADMIN_EMAIL และ MAIL_SENDER_EMAIL มีค่าเริ่มต้นเป็น peerapas.c@ku.th
- ถ้า deploy ให้ลูกค้าแล้วลืมตั้ง env บัญชีคุณจะเป็น admin ของระบบลูกค้าโดยอัตโนมัติ
- วิธีแก้: ไม่ใส่ค่าเริ่มต้น และบังคับต้องตั้ง env นอก dev/test เหมือน AUTH_SECRET

🟡 เล็กน้อย

- เชิญสมาชิกแล้วส่งเมลไม่สำเร็จ: user ถูกสร้างไปแล้วแต่ตอบ 503 เชิญซ้ำจะได้ 409 ต้องกด "ส่งคำเชิญอีกครั้ง" แทน
- ยกเลิกคำเชิญของคนที่ยังไม่เคย login ต้องติ๊ก "ยอมรับความเสี่ยงข้อมูลออฟไลน์" ซึ่งไม่เกี่ยวกับกรณีนี้
- หน้าสมาชิกแสดง "ยังไม่ได้ตั้งค่า SMTP" ชั่วขณะระหว่างโหลด
- SMTPMailer บังคับ STARTTLS เสมอ ใช้ mail catcher ตอน dev (เช่น Mailpit) ไม่ได้
- ไม่มีการกำหนดความยาวขั้นต่ำของ AUTH_SECRET
- Data endpoint ใช้เวลาประมาณ 320 ms ต่อ request เพราะ SQL store โหลด state ทั้งหมดทุกครั้ง เป็นปัญหาเดิมบน main ไม่ได้เกิดจาก PR นี้
