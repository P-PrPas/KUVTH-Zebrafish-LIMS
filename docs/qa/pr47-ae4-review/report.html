การแก้ไขที่ยืนยันแล้ว

Manifest บันทึก fingerprint ของแถวที่ import สร้างขึ้นใหม่ การ rollback ใช้ transaction และ shared write lock ตรวจ fingerprint, pending correction และ foreign-key references ก่อน soft-delete ทั้งชุด ลิงก์ specimen ที่ลบจำกัดเฉพาะ import_job_id นั้น

Tests ยืนยัน 409 หลังแก้แถวเดิมหรือเพิ่ม dependent row และ job ยังคง committed จากนั้น rollback สำเร็จเมื่อเอา dependency ที่สร้างเพื่อทดสอบออก

เปิด dashboard ด้วย member ที่ 320/375px: task reminder รูปนกและข้อความงานค้างเบียดกับเมนูสรุปผลด้านบน ควรจัด reminder เป็นแถวแยกหรือ compact badge และตรวจขอบเขตปุ่ม/ข้อความ ไม่ใช้เพียง scrollWidth ตัดสิน responsive ผ่าน หลักฐาน: member-mobile-375.png และ member-mobile-320.png เป็นจุดที่พบเพิ่มจาก visual QA ไม่ได้เกิดจาก diff rollback ล่าสุด

ข้อจำกัดที่ยังต้องรับทราบ

ประเด็นสถานะ / งานต่อ
Import เก่าหรือแตะข้อมูลเดิมงานก่อนมี manifest และงานที่แก้ existing rows ไม่ได้รับความสามารถ rollback ใหม่นี้ ต้องใช้ behavior เดิมแบบ conservative; ไม่ใช่ regression ใหม่
SMTP productionทดสอบ transport กับ localhost แล้ว แต่ยังไม่ยืนยัน TLS/credential/deliverability ของผู้ให้บริการจริง
Offline หลายอุปกรณ์Frontend tests ผ่าน แต่ไม่ได้จำลอง conflict พร้อมกันหลายอุปกรณ์ใน browser รอบนี้
Correction / timingเปิดหน้าและทดสอบ suite ที่เกี่ยวข้องตามที่มี ไม่ได้ทำทุก reject/withdraw/concurrency และ timing version scenario ใหม่
ข้อมูลวิทยาศาสตร์และระบบจริงต้องมี golden dataset ที่ลูกค้ารับรอง และ acceptance ของ TLS/load/monitoring/restore/customer browsers; รอบนี้ไม่ได้ทำ restore ใหม่

ไม่พบ defect ใหม่ที่ยืนยันเป็น blocker จึงไม่มีข้อเสนอแก้ application source ในรอบนี้ ข้อจำกัดข้างต้นเป็นขอบเขต acceptance ที่เหลือ ไม่ใช่หลักฐานว่าระบบล้มเหลว
