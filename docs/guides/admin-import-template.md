# Admin Excel import template v1

The primary onboarding path is now a system-owned template. Download it from
Admin → Import → **Download Excel template**. Its Reference sheet reflects active
master data at download time. The importer does not need the customer's Rev1
workbook on the deployed server.

Headers follow column A of `[Rev1]20260916_researcher-schema-mockup.xlsx`, rather
than the customer's source headers or positional V1/V2 layouts. Existing jobs
and the legacy import paths remain readable.

## Workflow

1. Create missing master data in the application, then download a fresh template.
2. Fill rows beginning at row 2. Preserve sheet names and column names. Paste
   values, not formulas. Unused data sheets may remain empty or be removed.
3. Upload the workbook. The seven data sheets are selected automatically.
4. Create the draft, then select **Validate all records**. Errors identify the
   sheet, source row and field. Correct working values in review or upload a
   corrected file. Header/formula problems require a corrected upload.
5. Review and confirm. Confirmation repeats validation against current database
   contents and commits all records together. No partial import, silent skipping,
   automatic master creation or overwriting existing records is allowed.

## Sheet contract

| Sheet | One row represents | References |
|---|---|---|
| `experiment_batch` | One activation lot, with repeated experiment metadata | `batch_code`, `lot_no`, master names/codes |
| `embryo` | One explicitly tracked embryo | `batch_code` + `lot_no` |
| `clone_fish` | One fish and its explicitly supplied current status | Optional `embryo_code` |
| `embryo_observation` | One observed embryo checkpoint | `embryo_code`, `stage`, `observer` |
| `fish_observation` | One fish on one calendar day | `fish_code`, `observer` |
| `control_arm_count` | Aggregate QC counts for one batch/arm/stage | `batch_code`, `stage` |
| `specimen` | One sample from a fish | `fish_code` |

This is a long-row format. An observation matrix must be converted to one
observation per row by the customer. The system does not infer observations or
individual embryos from counts. Referenced entities may be in the same upload
or already exist in the application.

Repeated `batch_code` rows must agree on date, site, operator and treatment.
They must have different `lot_no` values. A new upload cannot add lots by
redeclaring an existing batch in `experiment_batch`; it may reference existing
lots from `embryo` instead. Duplicate entity codes and observation identities
are rejected, including duplicates across jobs.

## Deliberate clarifications to Rev1

- IDs and `running_no` are generated by the application. They are not input
  columns. `embryo_code` may be omitted; its deterministic value is
  `{batch_code}_{lot_no}_{seq_in_lot}`. Use that value in referencing sheets.
- `site`, `operator`, `observer`, `treatment_group`, and `fish_box` are readable
  master codes/names, resolved to database IDs. They must match one active item.
- `donor_derivation` maps to donor-cell-line `preservation`. Donor matching uses
  strain, preparation, preservation and batch code. The fish sheet includes
  derivation and batch code to resolve donors unambiguously. When linked to an
  embryo, an omitted donor and DOB are taken from its activation lot.
- `sex` accepts `M`, `F`, `UNKNOWN`. Use `UNKNOWN` for Rev1's `ND`.
- Use explicit `ALIVE`, `DEAD`, etc. The Rev1 notes contradict each other on
  binary 0/1 meaning; the new importer accepts neither binary interpretation.
- `biological_condition` accepts `NORMAL`, `ABNORMAL`, `UNDETERMINED`.
  Free-form descriptions of health belong in fish `remarks`.
- `NBD` becomes `NATURAL_BREEDING`. QC accepts `NATURAL_BREEDING` and `IVF`.
- A timestamp without an offset uses the experiment site's timezone. Date-only
  embryo observations are rejected because they cannot support exact timing.
  Fish `observed_on` is a Bangkok calendar date. ISO dates are required.
- A terminal fish status requires a known `exit_date` and matching `exit_reason`.
  Do not manufacture an exit date from an old survival flag. Use `UNKNOWN` when
  current status is not established. Historical observations do not infer the
  fish's present-day status.
- One active protocol is required. Batch timing profiles are pinned using the
  existing application creation logic. Embryo observations use stages 1–26 and
  calculate HPA and expected/deviation snapshots from the pinned profile.

## Current limits

The template path writes canonical entities and observations. It uses the
existing durable import draft, source-file retention, row review and audit
mechanisms. SQL confirmation uses the same sequence serialization as normal
application writes and persists canonical rows plus job status in one transaction.

The legacy whole-job revert does not support the complete canonical template
graph. Its button is hidden for template jobs; corrections should use the
application's correction workflow. Legacy imports retain their existing revert.
Validation reports the first data error per attempt; header and formula issues
are listed in the draft. No new schema migration is required.
