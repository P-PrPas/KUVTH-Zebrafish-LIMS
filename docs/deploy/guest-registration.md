# KU registration and passwords

Anyone with an `@ku.th` email can register. Registration sends a six-digit email code; verification is required before a password is stored or the account can sign in. New users receive `guest` access to the central dashboard's unfiltered totals only. An admin grants `member` access in **Lab members**, using the role selector and **Save access**. Existing admin-only restrictions still apply to members.

Passwords are 8–128 characters and stored as salted PBKDF2-SHA256 hashes with 600,000 iterations. Five failed password attempts lock the account for 15 minutes. Login uses the existing HttpOnly session cookie. Roles are checked on every API request, so promotions and demotions affect existing sessions immediately. Guests can refresh access from their dashboard; other sessions refresh on reload or reconnect.

Existing accounts keep their roles and IDs. Choose **Forgot password / Set your first password** on the login page, enter a new password, and verify the email code. This also resets forgotten passwords and revokes previous sessions without deleting offline work. Legacy email-code endpoints remain for existing clients; creating a new guest session requires setting a password.

Deploy migration `000023_guest_password` for PostgreSQL or MySQL using the existing migration runner. Version 23 follows the running deployment's version 22, so existing databases apply the new password columns instead of skipping them. Configure SMTP before registration or password recovery; these flows cannot complete without email delivery. Use HTTPS and secure cookies in production. Do not roll back this migration while guest accounts exist: rollback refuses guests rather than deleting them or granting member access.

If antivirus or a managed network intercepts SMTP TLS, Docker needs the same trusted root CA as the host. Verify the certificate fingerprint against the host trust store, append that public CA to the container's standard CA bundle, mount the combined bundle read-only, and set `SSL_CERT_FILE` to its container path. Keep certificate verification enabled. This machine's AVG fix uses `%TEMP%/vetku-pr43-smtp/smtp-ca-bundle.pem` and the local Compose override `%TEMP%/vetku-pr43-smtp/local-tls.json`; include that override when recreating the API container. These machine-specific files are not part of the repository.
