# รีวิวหน้าจอหลังปรับระยะฟอร์ม

ทำงานบน `feat/kuvacb-redesign-v2` ใน repository หลัก ข้อเสนอด้านล่างยังไม่ได้ลงมือปรับ

## แก้ไขตามคำขอแล้ว

- หน้า Login ใช้ `ResearchArtwork` แบบ static เช่นเดียวกับ Dashboard ไม่มี animation ของภาพ แสง หรือปุ่มควบคุม motion
- ถอดบล็อกข้อความท้าย sidebar รวมข้อความ “ทุกบันทึกมีความหมาย” / “Every record matters” และ CSS ที่ไม่มีผู้ใช้งานแล้ว
- Rebuild และ recreate เฉพาะ frontend ด้วย `--no-deps` ทุก service healthy และ health endpoint ผ่าน ไม่รัน seed หรือเปลี่ยน volumes

## ขอบเขตการตรวจ

ตรวจหน้าหลักทั้ง 11 ส่วน: Dashboard, การทดลอง, ตรวจตัวอ่อน, ปลา, เลื่อนระยะ, กลุ่มเปรียบเทียบ, เวลามาตรฐาน, ส่งออก, ข้อมูลอ้างอิง, ประวัติการแก้ไข และสมาชิก รวม Login/สมัคร/ตั้งรหัสผ่าน/Guest

ตรวจ Dashboard ทั้ง 3 แท็บ รายละเอียดการทดลอง ฟอร์มสร้างทดลอง ฟอร์มขึ้นทะเบียนปลา ทะเบียน/รายละเอียด/ตัวอย่างของปลา ตัวอย่างรายงาน Audit ก่อน–หลัง HPA และหมวดข้อมูลอ้างอิงพร้อมฟอร์มทั้ง 7 หมวด รวมส่วนสิทธิ์และ session ของสมาชิก

ใช้ compiled frontend จาก Docker ที่ port 5173 และ isolated headless Chrome ตาม workflow เดิม ข้อมูลเป็น fixture ที่ intercept API ไม่ใช้บัญชีจริง การตรวจ layout หลักอยู่ที่ 1440 และ 375px และตรวจหน้าสำคัญเพิ่มที่ 820 และ 320px

- [104 browser checks](review-round-checks.json) ผ่านการตรวจ page overflow, ภาพ และเงื่อนไขเฉพาะหน้าที่เกี่ยวข้อง ไม่มี error alert ในชุดข้อมูลที่ตรวจ
- ภาพ Login และ Dashboard มี `data-motion="static"`, animation ใน subtree เป็นศูนย์ และไม่มี motion controls
- Auth/artwork tests เดิมผ่าน 16 tests ใน 2 files
- Biome, TypeScript และ production build ผ่าน
- ตรวจภาพด้วยตาแยกจาก checks: พบข้อความชนกันภายในหมวดข้อมูลอ้างอิงบนมือถือ แม้ page overflow check จะผ่าน จึงไม่ถือว่า visual QA ทุกจุดผ่านแล้ว

## ข้อเสนอเรียงลำดับ

### 1. หมวดข้อมูลอ้างอิง: แก้การบีบข้อความบนมือถือ

[ภาพที่พบ](review-round-master-category-3-375.png): ปุ่มทั้ง 7 หมวดอยู่แถวเดียว ชื่อหมวดถูกบีบและบางข้อความล้ำเข้าไปในปุ่มข้างเคียง โดยเฉพาะชื่อที่มีภาษาอังกฤษต่อท้าย

ใช้รายการหมวดแนวตั้งบน desktop และ selector ที่มี label บนมือถือ แสดงชื่อหมวดเต็มเพียงหมวดที่เลือก พร้อมพื้นที่เนื้อหาด้านขวาหรือด้านล่าง ใช้สี active และเส้นแบ่งแบบเดียวกับ navigation ปัจจุบัน เป็นจุดที่ควรแก้ก่อนงานตกแต่งอื่น

### 2. ส่งออกและรายงาน: ทำให้เป็นเอกสารขององค์กร

[ตัวอย่างรายงาน](review-round-report-preview-1440.png) ยังมีหัวข้อไทยปนอังกฤษ KPI จำนวนมากเรียงน้ำหนักเท่ากัน และเปอร์เซ็นต์ 92.00% แยกบรรทัดบน desktop ต่างจาก Dashboard

จัดหน้าส่งออกตามวัตถุประสงค์ของไฟล์ให้ชัด และจัดตัวอย่างรายงานด้วยหัวเอกสาร KUVACB, ช่วงข้อมูล/ตัวกรอง/เวลาสร้าง, KPI หลักกับข้อมูลประกอบ, section และตารางที่สม่ำเสมอ รักษาหน่วยติดกับตัวเลข ทำภาษาให้ตรงกับภาษาที่เลือก และตรวจการแบ่งหน้าพิมพ์รวมถึงหัวตารางที่ต่อหน้า ไม่เปลี่ยนสูตรวิเคราะห์หรือความหมายข้อมูล

### 3. ส่วนหัวมือถือ: ให้พื้นที่กับงานมากขึ้น

[ตรวจตัวอ่อน](review-round-checkpoint-375.png) และ [ตรวจปลา](review-round-fish-375.png) มีส่วนหัวหลายชั้นก่อนถึงงานจริง ทั้ง logo/navigation, ผู้ปฏิบัติงาน, สถานะ, บัญชี และคำอธิบาย

รวมสถานะเครือข่าย/การบันทึกในพื้นที่ที่กระชับขึ้น ลดข้อความซ้ำ และจัด heading/คำอธิบาย/ปุ่มให้มีลำดับชัด เก็บชื่อผู้ปฏิบัติงาน การเตือน และ touch target ที่อ่าน/กดได้ ไม่ซ่อนข้อมูลที่จำเป็นต่อการบันทึก

### 4. รายละเอียดทดลองและปลา: อ่านเหมือนทะเบียนงานวิจัย

[รายละเอียดทดลอง](review-round-experiment-detail-1440.png) และ [รายละเอียดปลา](review-round-fish-detail-375.png) ยังปรับการจัด metadata กับเหตุการณ์ให้ต่อเนื่องขึ้นได้ บนมือถือแถบข้อมูลปลา 5 ช่องเหลือพื้นที่ว่างหนึ่งช่อง

ใช้ส่วนหัวทะเบียนที่มีรหัส สถานะ และข้อมูลสำคัญในตำแหน่งคงที่ จัด metadata ที่จำนวนคี่ให้ช่องสุดท้ายเต็มแถว จัด timeline ตามวันที่ และวาง action แก้ไข/ลบในตำแหน่งเดียวกัน รูปแบบวันเวลาและข้อความรองควรเป็นมาตรฐานเดียวกัน ข้อมูลที่ fixture เว้นไว้ไม่ถือเป็นข้อบกพร่องของข้อมูลจริง

### 5. Guest: ให้หน้าตาอยู่ในระดับเดียวกับระบบหลัก

[Guest desktop](review-round-guest-1440.png) จัด KPI เป็น 5 + 1 การ์ด ทำให้แถวล่างเหลือการ์ดเดี่ยวและพื้นที่ข้างกันกว้าง

ใช้ส่วนหัวองค์กรที่กระชับ แสดงสิทธิ์เป็นข้อความบริบท และจัด 6 KPI เป็น 3 × 2 บน desktop / 2 × 3 บนมือถือ ให้ปุ่มตรวจสิทธิ์กับออกจากระบบมีน้ำหนักที่เหมาะสม ใช้เฉพาะข้อมูลรวมที่ Guest มีสิทธิ์อยู่แล้ว

### 6. ภาษาและรายละเอียดร่วม: เก็บงานให้สม่ำเสมอ

ยังมีคำไทยปนอังกฤษ เช่นชื่อ KPI ในรายงาน, Active/Inactive และข้อความเชิงคำขวัญที่ Login ใช้ชื่อ/คำอธิบายตรงกับหน้าที่ของระบบ เช่น “ระบบงานวิจัยปลาม้าลาย” และใช้คำเฉพาะทางอังกฤษเมื่อจำเป็น

รักษา Prompt/Noto Sans Thai และสี KUVACB เดิม จัดขนาด heading, น้ำหนักคำอธิบาย, ตัวเลข, badge และลิงก์ action ให้สม่ำเสมอ แยก empty/error/loading ให้มีคำแนะนำที่ตรงกับสถานะ ใช้การเปลี่ยนสถานะสั้น ๆ เฉพาะที่ช่วยบอกผลการกด ไม่เพิ่มภาพเคลื่อนไหวต่อเนื่อง

## ข้อจำกัด

เป็นการตรวจหน้าจอและ fixtures ไม่ใช่การทดสอบทุก workflow กับบัญชี/ข้อมูลจริง ไม่มี physical-device performance test และไม่ได้ทดสอบการพิมพ์ทุกขนาดกระดาษ รอบนี้ไม่ได้รัน backend/full unit suite เพราะแก้เฉพาะการแสดงผลสองจุด Vite ยังแจ้ง JS bundle เกิน 500kB ตามเดิม
