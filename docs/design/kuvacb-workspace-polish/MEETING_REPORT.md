# รายงานสำหรับประชุม

ปรับบน `feat/kuvacb-redesign-v2` ตาม feedback ว่า PDF เดิมมีเนื้อหามากเกินไปและขาดกรอบตาราง

## รูปแบบใหม่

- ค่าเริ่มต้นคือ **สรุปสำหรับประชุม 2 หน้า A4** ใช้ snapshot และตัวกรองเดียวกับรายงานเดิม
- หน้า 1: หัวองค์กร ขอบเขตข้อมูล เวลาสร้างและเวอร์ชันเวลามาตรฐาน, KPI หลัก 4 ค่า, กระบวนการ 5 ขั้น, ผลระยะตัวอ่อนและสถานะปลา พร้อมคำอธิบายฐานการนับ
- หน้า 2: รายการขาดผลตรวจนานที่สุด, กลุ่มที่มีขนาดมัธยฐานความคลาดเคลื่อนสูงที่สุด และผล SCNT/กลุ่มควบคุมที่มีจำนวนตัวอย่างมากที่สุด อย่างละไม่เกิน 5 รายการ
- แต่ละตารางหน้า 2 ระบุจำนวนที่แสดงจากทั้งหมดและเกณฑ์การเรียง ผลเปรียบเทียบไม่ได้อ้างว่ากลุ่มตัวอย่างที่มากกว่ามีผลสำเร็จดีกว่า
- **รายงานวิเคราะห์ฉบับเต็ม** เลือกแยกได้ มีตารางครบทุกแถว จำนวนหน้าขึ้นกับข้อมูล ไม่ต้องเปลี่ยนตัวกรองหรือโหลด snapshot ใหม่เมื่อเปลี่ยนรูปแบบ

## การจัดหน้า

- หัวข้อมีกรอบและเส้นแบ่ง, KPI มีกรอบแต่ละช่อง, ตารางมีเส้นครบทั้งแนวตั้งและแนวนอน รวมแถวสุดท้าย
- ตัวเลขในรายงานประชุมชิดขวา ใช้ตัวเลขความกว้างคงที่ และพิมพ์เลขหน้ากับชื่อระบบในขอบกระดาษ
- กรอบยังเห็นเมื่อปิดการพิมพ์พื้นหลัง ใช้ A4 และ margin ของเอกสาร ไม่พึ่งสีพื้นเพื่อแยกเนื้อหา
- แบ่งหน้า 2 ชัดเจนและเก็บแต่ละตารางสรุปไว้ด้วยกัน หัวตารางรายละเอียดซ้ำเมื่อข้ามหน้า และเก็บ legend กับกราฟแต่ละสถานที่ไว้ในหน้าเดียวกัน
- ตารางปลา 12 คอลัมน์แยกเป็น 2 ตาราง 6 คอลัมน์: การรอดตามอายุ และสถานะ/เพศ/ตู้ปลา โดยเก็บทุกแถวเดิม
- ตัดกราฟการสูญเสียที่เคยซ้ำในหัวข้อกระบวนการ เหลือในหัวข้อการสูญเสียที่ตรงกับเนื้อหา
- แสดงชื่อสถานที่และกลุ่มในตัวกรองแทน UUID เมื่อมีข้อมูลอ้างอิง และแสดงองค์ประกอบกลุ่มเวลาตรวจให้ครบ
- ค่าที่ยังไม่มีข้อมูลยืนยันไม่ถูกแสดงเป็นศูนย์ในสรุปและตารางการรอด คำเตือนข้อมูลต้นทางไม่ครบแสดงในสรุปเมื่อ snapshot ระบุไว้

## หลักฐานการตรวจ

- Frontend suite: **193 tests / 27 files ผ่าน** รวมการเรียงและจำกัดรายการจาก 500 แถวต่อชุด, การคงทุกแถวในฉบับเต็ม, การอ่านชื่อสถานที่, ค่าที่ยังไม่ยืนยัน, สถานะ loading/error และการดาวน์โหลดเดิม
- Biome, TypeScript และ production build ผ่าน ไม่มี dependency เพิ่ม; Vite ยังคงมีคำเตือน bundle >500kB
- [Browser checks](meeting-browser-checks.json): 12 checks บน Docker frontend รุ่นล่าสุด ครอบคลุม 1440/820/375/320px ทั้งสองรูปแบบ และการพิมพ์ 4 แบบ ไม่พบ page overflow หรือ domain writes
- [PDF checks](meeting-print-checks.json): สรุปไทย 2 หน้า, ไทยปิดพื้นหลัง 2 หน้า, อังกฤษชุด 500 รายการพร้อมตัวกรองและข้อมูลไม่ครบ 2 หน้า, ฉบับเต็มไทยชุดตัวอย่าง 4 หน้า ไม่พบข้อความนอกขอบกระดาษ และ render เพื่อตรวจทุกหน้า
- Rebuild/recreate เฉพาะ frontend ด้วย `--no-deps` API/PostgreSQL และข้อมูลเดิมยังอยู่
